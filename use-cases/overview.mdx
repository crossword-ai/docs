The rest of these docs describe one object at a time: a welcome message, a Rulebook, a Campaign. A use case page puts them together. Each one follows a single shopper on a generic storefront, shows what they see, and then works backwards to the Journeys, components, rules, and orchestration that produced it. Read these when you know what you want a shopper to experience and want to see how the pieces combine in Crossword before you build it yourself.

## How to read a use case

Every walkthrough has the same four sections.

| Section | What it answers |
| ------- | --------------- |
| What the shopper sees | The moment on the storefront, told from the shopper's side. No configuration yet. |
| Building blocks used | Every component and orchestration object involved, and the rule on each component that carries one. |
| Step by step | The order to build it in the Crossword dashboard, from an empty experience to a published revision. |
| Measuring it | The goal event and the events emitted along the way, so you can tell whether it worked. |

The walkthroughs use a sneaker storefront, Product A and Product B, and prices in US dollars. Swap in your own catalog. The structure does not change.

Two ideas from [Core concepts](/concepts) come up on every page. Rules live on components, not on Journeys, so each walkthrough lists the rule on every component that carries one. Journeys are not mutually exclusive, so each walkthrough shows what happens when its Journey runs alongside the Default and any others you have enabled.

## Example

The screenshot below is the sneaker storefront every walkthrough builds on, captured on its home page before anything happens. A hero banner reads "Movement that looks good" with a **Shop now** link in its corner, and a "Sneaker Launches" heading starts below it. Floating over the page is the Crossword launcher, a pill that reads **Ask anything** with a keyboard shortcut beside it, and the widget is closed. Nothing is annotated and no Journey has fired yet. It is the plain starting point that each use case changes.
