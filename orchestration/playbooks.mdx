A Playbook is a reusable collection of contextual behaviors that Crossword applies when relevant. It lets you group everything a shopper in one situation should see, such as arriving from a video or returning with items in their cart, without writing that situation into every component by hand.

A Playbook does not switch on as a whole. Each rule-based component inside it carries its own rule. Enabling the Playbook makes those rules eligible for evaluation, and the Rulebook for each component type decides what actually shows.

## Example

A Playbook called YouTube Unboxing serves shoppers who arrive from an unboxing video. Every row is a separate component with its own rule.

| Component | Rule inside the Playbook |
| --------- | ------------------------ |
| Welcome message | If source is YouTube Unboxing A, use message X |
| Conversation starter | If the product from the video is available, show "Shop the pair from the video" |
| Conversation starter | If the product is unavailable, show "Find something similar" |
| Content block | On a product page, show video-specific product context |
| Proactive message | If 15 seconds pass with no engagement, offer sizing assistance |
| Recommendation section | If the featured SKU is unavailable, show alternatives |

Read the full walkthrough in [YouTube unboxing playbook](/use-cases/youtube-unboxing-playbook).

## What it contains

| Concept | Meaning | Example |
| ------- | ------- | ------- |
| Name and description | What the Playbook is for | "YouTube Unboxing: shoppers arriving from unboxing videos" |
| Enabled or disabled | Whether the Playbook's rules are eligible for evaluation | Enabled |
| Default designation | Marks the one Playbook that supplies baseline settings and fallback content | Default Playbook |
| Appearance and response settings | Baseline look, tone, and reply behavior for the experience. Supplied by the Default Playbook | Brand colors, reply length |
| Conversation components | Welcome messages, conversation starters, follow-up suggestions, and proactive messages, each with its own rule | A welcome message for video arrivals |
| Agents | The configured assistants this Playbook makes available, each with a routing rule | A shopping assistant |
| Page sections | Content blocks, page suggestions, recommendation, comparison, social proof, and offer sections, and dynamic landing page configurations, each with a rule, a target page, and a placement | Video context on a product page |

## The Default Playbook

Every experience has exactly one Default Playbook. It does two jobs.

- It supplies the baseline **appearance and response settings** for the experience.
- It supplies the **fallback** for every Rulebook. Its components carry no rule, or a rule that always matches, at priority 0.

The Default Playbook guarantees a shopper always sees a welcome message and always has starters, even when no other Playbook applies. It cannot be disabled.

## Two principles

**Rules belong to components, not to Playbooks.** There is no master condition on a Playbook. Each welcome message, starter, proactive message, Agent, and page section inside it carries its own conditions, timing, priority, and delivery restrictions. Cards and interactive components placed inside them carry no rule. Read [Rules](/orchestration/rules).

**Playbooks are not mutually exclusive.** A visitor can qualify for YouTube Unboxing, Returning Customer, and VIP Customer at once. The Playbooks do not fight. Each contributes candidates to the relevant Rulebook, and the Rulebook resolves them. Read [How rulebooks resolve conflicts](/orchestration/how-rulebooks-resolve).

## How it fits

A Playbook lives inside an experience. Below it sit the components it holds. The rule-based ones decide when they show. The cards and interactive components placed inside them come from the shared Component library and carry no rule of their own.

Three things act on Playbooks from outside.

- **Rulebooks** take the eligible rules from every enabled Playbook and decide what shows.
- **Campaigns** can activate a Playbook for a shopper for a defined scope or lifetime, such as their next visit. Read [Playbooks vs campaigns](/orchestration/playbooks-vs-campaigns).
- **Experiments** split traffic between two or more Playbooks and measure a goal. Read [Experiments](/orchestration/experiments).
