title: "Routing"
description: "How a conversation reaches the right Agent"

Routing decides which Agent answers a conversation. Each Agent carries a routing rule, and the agent routing Rulebook resolves those rules to one winner. A shopper never chooses an Agent.

A routing rule is a rule like any other, with conditions, condition combinations, and a priority. Read [Rules](/orchestration/rules) for the full reference.

## Example

An order assistant's routing rule reads: the shopper is signed in, and the topic is an order. A signed-in shopper opens chat on the cart page and types "where is my parcel?". The rule matches, and the order assistant takes the conversation.

The combination is set to All, and one exclusion reads Member of "Open support ticket". Priority is 10. A summary beneath the editor lists the other eligible Agents, Shopping assistant at 0 and VIP stylist at 20, so you can see where this rule sits.

## What it contains

| Setting | What it controls | Example |
| ------- | ---------------- | ------- |
| Conditions | When this Agent is a candidate | Signed in, and topic is an order |
| Condition combinations | Whether all or any conditions must match, and which exclude the Agent | All, excluding members of "Open support ticket" |
| Priority | Which candidate wins when more than one Agent matches | 10 |

Routing rules carry no timing and no delivery restrictions.

## What a routing rule can test

| Condition | What it tests | Example |
| --------- | ------------- | ------- |
| Signed in | Whether the shopper is authenticated | Shopper is signed in |
| Page or URL | Where the shopper opened the conversation, by page type or path | Page type is cart |
| Segment membership | Whether the shopper's profile is in a segment | Member of "VIP customers" |
| Session behavior | What the shopper has done this session, including cart contents | Cart contains Product A |
| Topic | What the shopper's message is about | Topic is an order, a return, or sizing |

Topic is the one condition specific to routing. Crossword reads it from the shopper's message, so order questions and product questions can reach different Agents in the same session.

## How the Rulebook resolves

The agent routing Rulebook returns one result. It evaluates the routing rule of every Agent in every enabled Playbook, walks the matching candidates from the highest priority down, and takes the first. Ties go to the more specific rule, then to the most recently updated.

When no rule matches, the conversation goes to the Agent in the Default Playbook. It sits at priority 0 and always matches, so every conversation reaches an Agent. Read [How rulebooks resolve conflicts](/orchestration/how-rulebooks-resolve).

## Handoff from a Campaign

A [Campaign](/orchestration/campaigns) step can hand a shopper to an Agent when a sequence needs a live conversation. The step names the Agent, so routing rules are not evaluated for that handoff.

## When conditions change mid-conversation

The Agent that takes a conversation keeps it. Routing is evaluated again on each shopper message, but the current Agent only loses the conversation when a routing rule with a higher priority than its own now matches. A new page or a new topic can trigger that. A rule at equal or lower priority cannot.

## Worked example

Three Agents are eligible.

| Agent | Playbook | Routing rule | Priority |
| ----- | -------- | ------------ | -------- |
| Shopping assistant | Default | Always matches | 0 |
| Order assistant | Default | Signed in, and topic is an order | 10 |
| VIP stylist | VIP Customer | Member of "VIP customers", and page type is product | 20 |

A signed-in VIP shopper opens chat on the cart page and asks "where is my order?". The VIP stylist does not match, because the page is not a product page. The order assistant matches at 10 and the shopping assistant at 0. The order assistant wins.

The same shopper moves to a product page and asks "does this come in white?". The VIP stylist now matches at 20, higher than the order assistant's 10, so the VIP stylist takes over.

## How it fits

Routing is the one part of an Agent that a Rulebook reads. Everything else applies only after the Agent has won. Enabling a Playbook makes its Agents' routing rules eligible.
