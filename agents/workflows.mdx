---
title: "Workflows"
description: "Deterministic steps, branches, confirmations, and handoffs an agent can run"
---

A Workflow is a set of steps that an Agent or a Campaign can run to complete an operational task. It gives the parts of a conversation that must be exact, such as looking up an order or generating a return label, a fixed path with defined inputs, outputs, and error handling.

Use a Workflow whenever the outcome has to be the same every time. An Agent decides when to call it. The Workflow decides what happens once called.

## Example

A Workflow called Generate return label takes an order number and the items to return. It checks eligibility, asks the shopper to confirm the items, creates the label, and returns a link. If the order is outside the return window, it branches to a response that explains why and hands the conversation back to the Agent.

## What it contains

| Concept | Meaning | Example |
| ------- | ------- | ------- |
| Inputs | The values a Workflow needs before it runs | Order number, item list |
| Outputs | The values a Workflow returns to the caller | Label URL, eligibility status |
| Steps | The ordered nodes the Workflow runs | Look up order, confirm items, create label |
| Error handling | What happens when a step fails | Retry the lookup once, then respond with an apology |
| Timeout handling | What happens when a step takes too long | After 30 seconds, hand off to the Agent |

## Step types

| Step type | What it does | Example |
| --------- | ------------ | ------- |
| Deterministic operation | Runs a fixed action against your systems | Look up an order, apply a coupon, update an attribute |
| Agent invocation | Asks an Agent to produce content or a judgement inside the Workflow | Summarize the reason for the return |
| Condition or branch | Chooses the next step from the values so far | Is the order within the return window? |
| Confirmation or approval | Pauses until the shopper or an operator confirms | "Return these two items?" |
| Response or handoff | Sends a reply to the shopper, or hands the conversation to an Agent | "Your label is ready" with a link |

## Error and timeout handling

Each Workflow defines what happens when a step fails and when a step exceeds its time limit. The options are the same for both: retry the step, branch to a different step, respond to the shopper, or hand off to an Agent. A Workflow that hits an unhandled error ends and returns control to whoever called it.

## Who can call a Workflow

- **An Agent.** The Agent's configuration lists the Workflows it can call, and its [permissions](/agents/guardrails-and-permissions) set the limits and confirmations on each. The Agent decides when the conversation needs one, passes the inputs, and uses the outputs in its reply. An Agent reads its [knowledge and context](/agents/knowledge-and-context) directly but changes nothing without a Workflow. Read [Agents](/agents/overview).
- **A Campaign step.** A Workflow call is a step type in a Campaign sequence. The Campaign passes the inputs and can branch on the outputs. Read [Campaigns](/orchestration/campaigns).

## How it fits

A Workflow sits beside Agents and Campaigns as a callable unit. It does not carry a rule, and it is not resolved by a Rulebook. Something else decides to run it. Once running, it can invoke an Agent for a single step and hand off to an Agent at the end.
