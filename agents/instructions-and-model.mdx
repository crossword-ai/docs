---
title: "Instructions and model"
description: "Responsibility, tone, instructions, and model settings"
---

Instructions tell an Agent what to do, how to speak, and what to prioritise. They are written in plain language, per Agent, alongside the Agent's name and responsibility. Model settings choose the model the Agent runs on and how it generates replies.

Routing decides which Agent answers. Instructions decide how it answers.

## What it contains

| Setting | What it controls | Example |
| ------- | ---------------- | ------- |
| Name | How the Agent is identified in the dashboard and in conversation history | Order assistant |
| Responsibility | What this Agent is for, in one line | Tracking, returns, and refunds |
| Instructions | What to do, how to speak, and what to prioritise, in plain language | Confirm the order number before any lookup |
| Tone | The voice the Agent uses | Warm and direct |
| Reply length | How long a reply should be | Two to three sentences |
| Model settings | The model the Agent runs on and how it generates replies | A fast model with low variation |

## Writing instructions

Write instructions as you would brief a new member of staff. Say what the job is, what good looks like, and what to do when a question falls outside the job. Three things belong in every set.

- What to do: the tasks the Agent handles, and the order it handles them in.
- How to speak: voice, formality, and anything about the brand's language.
- What to prioritise: what to do when two goals compete, such as answering fast versus confirming details first.

Anything the Agent must never say or do belongs in [Guardrails and permissions](/agents/guardrails-and-permissions), not in the instructions. Guardrails are enforced. Instructions are followed.

## Follow-up suggestions

[Follow-up suggestions](/components/conversation/follow-up-suggestion) are configured here, in the instructions. They carry no rule, no conditions, and no priority. On every reply, the Agent writes them from your guidance, the reply it just gave, and the Journeys that are enabled.

- **Product Q&A follow-ups** ask the next question about the products in the reply, such as comparing, sizing, price, or ingredients.
- **Journey follow-ups** take the shopper into a Journey you have built, such as a quiz Journey or a support Journey.

Say when to offer which kind, how many, and which Journeys to point to.

```text
After you recommend products, offer up to three follow-ups:
one to compare them, one about sizing,
and one that starts the quiz Journey if the shopper seems unsure.
```

The suggestion set in [Response configuration](/agents/response-configuration) still caps how many show.

## Per Agent, with a baseline

Instructions are per Agent. The shopping assistant and the order assistant on the same storefront have different instructions because they have different jobs.

The Agent in the Default Journey supplies the baseline. Its tone, reply length, and model settings are the experience's defaults, in line with the baseline response settings the [Default Journey](/orchestration/journeys#the-default-journey) provides. Every other Agent starts from that baseline and overrides only what its job needs.

## How it fits

Instructions apply once the agent routing Rulebook has picked the Agent. Read [Routing](/agents/routing). They shape the reply text within the limits set by [Guardrails and permissions](/agents/guardrails-and-permissions) and the components allowed by [Response configuration](/agents/response-configuration). An instruction cannot grant an action the permissions withhold, and it cannot add a component the response configuration excludes.

## Example

The order assistant on a sneaker storefront has instructions like these.

```text
You are the order assistant for a sneaker storefront.
Help signed-in shoppers track orders, start returns, and understand refund timing.
Always confirm the order number before you look anything up.
Speak plainly. Keep replies to two or three sentences unless the shopper asks for detail.
When a return is eligible, offer to generate the label instead of describing the steps.
If the shopper asks about products or sizing, say the shopping assistant can help with that.
Never promise a refund date. Give the range from the refunds policy instead.
```
