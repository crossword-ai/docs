Knowledge sources are what an Agent answers from, such as the catalog, product FAQs, and policies. Customer context is what the Agent knows about this shopper right now, such as the page they are on and where they came from. Each Agent gets only the knowledge and context its job needs.

## Knowledge sources

Knowledge sources are content you keep current. The Agent answers from them and cites nothing it cannot find in them.

| Source | What it holds | Example |
| ------ | ------------- | ------- |
| Catalog | Products, variants, prices, stock, and bestsellers | Every gummy, spray, and bundle |
| Product FAQs | Questions and answers about a single product | "Will I wake up groggy?" for the sleep gummy |
| Brand FAQs | Questions about the brand as a whole | Ingredients, sourcing, lab testing, vegan |
| Policies | Shipping, returns, guarantees, and contact details | The 30-day guarantee |
| Reviews | What customers say about a product | Review highlights for the product on screen |

Narrow each Agent to its job. An Agent on a product page answers best from that product's own FAQ, not the whole catalog. The global guardrails also hold every Agent to facts the brand has published. Read [Guardrails and fallback](/agents/guardrails-and-fallback).

The **Knowledge** screen lists your knowledge bases with their source count and sync status. Only synced knowledge can be used in a reply.

## Customer context

Customer context is live information about the shopper, supplied by Crossword for every conversation.

| Signal | What it tells the Agent | Example use |
| ------ | ----------------------- | ----------- |
| Page | Which page the shopper is on, down to the product | Answer about the product on screen |
| Arrival source | Where they came from, such as an ad, Google, or direct | Pick up the angle of the ad they clicked |
| Logged in | Whether the shopper is signed in | Offer an order lookup |
| Past orders | What the shopper has bought before | Offer a reorder of a product they already use |

Some context comes from Global settings and applies to every Agent. Customer context is what is true now. [Customer memory](/agents/customer-memory) is what the Agent has learned in the conversation and on earlier visits.

## Read versus change

An Agent reads its knowledge sources and customer context. It changes none of them directly.

Every change goes through an action, such as adding to cart or starting a return. Multi-step actions run as [Workflows](/agents/workflows). Read [Rich responses and actions](/agents/rich-responses-and-actions).

| The Agent wants to | How it happens |
| ------------------ | -------------- |
| Quote a pack price | Reads the catalog |
| Explain the return window | Reads a policy |
| Know the shopper came from an ad | Reads customer context |
| Add a pack to the cart | Runs an action |
| Start a return | Runs an action |

## Example

The Product Q&A Agent answers on product pages, so its knowledge and context stay close to the product on screen.

```yaml
knowledge_sources:
  - The product on screen and its own FAQ
  - Reviews, pack sizes, prices, Subscribe & Save, 30-day guarantee
customer_context:
  - Which product page they are on
  - Whether they have ordered this product before
  - Whether they came from an ad
```

A returning customer on the sleep gummy page gets a reorder offer, because past orders show they bought it before.
