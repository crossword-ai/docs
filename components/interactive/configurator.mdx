---
title: "Configurator"
description: "Options, constraints, a live preview, and a result the shopper can add to cart"
---

A configurator lets a shopper build or customize a single product by choosing from options. An engraving on a watch, the frame, wheels, and saddle on a bike, the fabric and legs of a sofa. It shows the result as the shopper chooses and ends in one configured product they can add to the cart, so a product with many combinations becomes a short set of choices instead of a wall of variants.

## Example

A shopper on the product page of a customizable running shoe asks the widget "Can I get these in black with a red sole?" The assistant reply holds a configurator with the live preview at the top, the shoe rendered in the current colors with the running price **$160** under it, and four options below in order: **Upper** with Black selected, **Sole** with Red selected, **Laces** as a row of swatches with **Neon** disabled because it is unavailable with the red sole, and **Size** as a size selector. Under the options, the result summary reads "Black upper, red sole, white laces, size 9. Ships in 2 to 3 weeks." and the **Add to cart** button is enabled at **$160**.

## Anatomy

| Property | What it holds |
| -------- | ------------- |
| Options | The choices the shopper makes, in order. Each option has a label, its available values, and a default. Values can carry an image and a price difference. Built from the [selector](/components/primitives#selector) and [input](/components/primitives#input) primitives. |
| Constraints | Which combinations are allowed. A value that is unavailable with an earlier choice is hidden or disabled, and a value that requires another is selected with it. |
| Live preview | The product as currently configured: an image or media that updates with each choice, and the running price. |
| Result | The configured product once every required option is set, with its summary, final price, and availability. |
| Add-to-cart control | The button that adds the configured product to the cart. Enabled only when the configuration is complete and valid. |

Options and constraints govern what the shopper can build once the configurator is on screen. They do not decide whether it shows. The result is added to the cart as one line item with its chosen values, so the [cart and checkout card](/components/cards/cart-checkout-card) shows the configuration the shopper made.

A configurator shapes one product. To let a shopper assemble several products into a set, use a [bundle builder](/components/interactive/bundle-builder).

## Where it appears

A configurator never shows on its own. One of these rule-based components includes it.

- In the [assistant reply](/components/conversation/assistant-reply), where the Agent chooses it. The shopper asks for a product in a combination that does not exist as a stock variant, or asks to personalize one, and the Agent answers with the configurator instead of listing combinations in text.
- In a [proactive message](/components/conversation/proactive-message), for example on a product page for a customizable product after the shopper has switched between several variants without adding one.
- On a page, inside a [content block](/components/page/content-block) on the product page of a customizable product, or inside an [offer section](/components/page/offer-section) when a discount applies to a configured product.

## Rules

A configurator carries no rule. It shows because a proactive message or a page section with a rule included it, or because the Agent composed it into the assistant reply. The rule that decides whether and when the shopper sees it lives on that component, not on the configurator. Read [Rules](/orchestration/rules).
