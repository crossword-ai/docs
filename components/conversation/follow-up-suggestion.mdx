---
title: "Follow-up suggestion"
description: "Suggested next prompts shown after an assistant reply"
---

A follow-up suggestion is a prompt a shopper sees directly under an assistant reply. Each one offers a next step that fits what the Agent just said, and tapping it sends that prompt back to the Agent. A new set appears with each reply, several at a time, up to the suggestion set's limit.

## Example

A shopper has told the Agent they run on roads, wear a size 9, and want to stay under a set budget. The Agent's reply, "Based on what you've told me, these three are your best matches", ends with a carousel of three product cards. Directly under the carousel sit three follow-up chips in a row: "Compare the first two", "Show me cheaper options", and "Only show black". They sit inside the reply, above the composer, and tapping one sends its text to the Agent as the shopper's next message. The next reply brings a fresh set.

## What it contains

| Property | What it holds |
| -------- | ------------- |
| Label | The text on the suggestion |
| Source | Generated by the Agent at reply time, or configured by you in advance |
| Action | What tapping the suggestion does. Usually it sends a prompt to the Agent |
| Relevance | How closely a generated suggestion fits the reply it follows. Used to rank it |
| Rule | The conditions and priority on a configured suggestion |

A follow-up holds its own label and embeds nothing from the [Component library](/components/overview). A [quick reply](/components/conversation/assistant-reply#quick-reply) is different. It is a closed answer with a fixed value, such as Yes or Size 9, and the Agent composes it into the reply itself.

## Rule

Follow-ups have no Rulebook. The Agent that wrote the reply produces the candidates, through its response configuration, and the suggestion set caps how many show. Two kinds of candidate qualify.

- **Generated** follow-ups are written at reply time from the reply and the conversation so far. They carry no rule. Relevance ranks them.
- **Configured** follow-ups are written by you in the Agent's response configuration and attached when their rule matches. Priority ranks them.

Only configured follow-ups carry a rule, and it is lighter than a starter's, because the reply it follows already narrows the context. Timing and delivery restrictions do not apply.

| Rule field | What you can set |
| ---------- | ---------------- |
| Conditions | Page or URL, segment membership, shopper attributes, session behavior |
| Condition combinations | All, any, and exclusions |
| Priority | Orders configured follow-ups against each other |

Which Agent answers, and so which response configuration applies, is decided upstream by the agent routing Rulebook. Read [Agents](/agents/overview) for routing and response configuration. The full list of conditions and how they combine is in [Rules](/orchestration/rules). For the contrast with components that a Rulebook does resolve, read [How rulebooks resolve conflicts](/orchestration/how-rulebooks-resolve).

## Suggestion set

Follow-ups render inside a suggestion set under the reply. The set is a setting on the follow-ups, not a component with a rule of its own. It is the only thing that limits how many follow-ups the shopper sees.

| Setting | What it controls |
| ------- | ---------------- |
| Maximum visible | How many follow-ups show under one reply |
| Ranking | The order of the visible follow-ups. Relevance for generated, priority for configured |
| Layout | How the visible follow-ups are arranged, such as a row of chips or a stacked list |
| Fallback set | The follow-ups shown when nothing qualifies |
