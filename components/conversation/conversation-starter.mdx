A conversation starter is a tappable prompt a shopper sees under the welcome message, before they type. Tapping one sends its prompt to the Agent. Several starters show at once, three to five, drawn by priority from every enabled Playbook by the conversation starter Rulebook.

## Examples

The same three-chip row on a sneaker storefront, first with nothing matching and then with one rule at a time adding its starters to the set.

### Out of the box

A shopper lands on any page and no rule from any other Playbook matches. Before the widget even opens, three chips from the Default Playbook stack above the launcher button in the corner of the page: "Help me brainstorm", "Explain a concept", and "What can you do?". Tapping one opens the widget with that prompt already sent. The same three chips sit under the welcome message once the widget is open. This is what every shopper sees when nothing else matches, because the Default Playbook's starters always match at priority 0 and fill whatever room is left.

### With a rule: arrival from a video

> Rule: UTM source is youtube and UTM campaign is unboxing-a, and the product on the page is in stock. Priority 10.

A shopper from the brand's unboxing video opens the widget on the product page for the pair in the video. The first chip now reads "Shop the pair from the video", followed by "Help me find a shoe" and "Track my order" from the Default Playbook. One starter from the higher-priority rule took the first slot, and the defaults filled the rest. Tapping the first chip sends that prompt to the Agent as if the shopper had typed it.

### With a rule: on a collection page

> Rule: path starts with /collections/running. Priority 8.

A shopper opens the widget while browsing the running collection. The row reads "Which of these is best for long runs?", "Show only my size", and "Track my order". The first two come from the collection rule, because the Rulebook is set to take two from the highest-priority match, and the last is a default. The chips now ask about the products on screen instead of the storefront in general.

### With a rule: product out of stock

> Rule: page type is product and the product on the page is out of stock. Priority 12.

A shopper opens the widget on a product page for a pair that has sold out. The first chip reads "Find something similar" and the second "Tell me when it's back", followed by "Help me find a shoe". The first label is generated at display time with `{product_name}` filled in, so it names the sold-out pair. Compare this with the video example: the same product page, a different stock state, a different first chip.

### With a rule: VIP segment

> Rule: shopper is a member of the "VIP customers" segment. Priority 20.

A VIP shopper opens the widget on the home page. Four chips show: "See early access drops", "Use my member discount", "Help me find a shoe", and "Track my order". The VIP rule outranks every other rule, so its two starters lead the row, and the Total setting of 4 leaves room for two defaults. A VIP shopper arriving from the video would see the VIP starters first and the video starter after them.

### What else a rule can do

- Match any of several referrers, so visitors from any social network share one set of starters.
- Use a shopper attribute, such as offering "Show size 9 only" when the preferred size is known.
- React to cart contents, such as leading with "Finish my checkout" when the cart has items.
- Respond to previous interaction, such as "Continue where I left off" for a shopper who chatted earlier this session.
- Exclude a segment, such as hiding order-tracking starters from shoppers who are not signed in.
- Carry fewer, shorter starters for mobile devices so the row fits on one line.
- Fill a generated label from the ad `{content}` the shopper arrived with.
- Combine page and campaign, so a starter shows only on product pages reached from one campaign.

Every condition and how they combine is in [Rules](/orchestration/rules).

## What it contains

| Property | What it holds |
| -------- | ------------- |
| Label | The text on the starter, written by you or generated at display time |
| Icon | An optional icon shown with the label |
| Action | What tapping the starter does. Usually it sends a prompt to the Agent |
| Rule | The conditions and priority that make this starter a candidate. One rule can carry several starters |

A generated label is written at display time from variables such as `{product_name}` or the ad `{content}` the shopper arrived with. Generated starters compete in the Rulebook exactly like written ones.

A starter holds its own label and embeds nothing from the [Component library](/components/overview). The assistant reply that follows a tap can render any card the library offers.

## Rule

A starter carries a rule with conditions and priority. Timing and delivery restrictions do not apply, because starters show once, together with the welcome message.

| Rule field | What you can set |
| ---------- | ---------------- |
| Conditions | UTM parameters, referrer or arrival source, page or URL, segment membership, shopper attributes, session behavior, device and browser |
| Condition combinations | All, any, and exclusions |
| Priority | Orders matching rules and decides which rule the Rulebook takes the first starters from |

The conversation starter Rulebook returns several results, up to a limit. It collects every matching rule from every enabled Playbook, orders them by priority, and builds the set with three settings.

| Setting | What it does |
| ------- | ------------ |
| Take from highest priority | How many starters to take from the highest-priority rule that matches |
| Then one from each | After that, take one starter from each remaining matching rule, in priority order |
| Total | The maximum number of starters to show. Choose 3, 4, or 5 |

The Default Playbook's starters, at priority 0, are always the last matching rule.

Read the [worked example](/orchestration/how-rulebooks-resolve#worked-example-conversation-starters) to see how the same candidates produce different sets under four different settings.

## Suggestion set

The starters the Rulebook returns render inside a suggestion set. The set turns the Rulebook's result into what the shopper sees. It is a setting on the starters, not a component with a rule of its own.

| Setting | What it controls |
| ------- | ---------------- |
| Ranking | The order of the visible starters. Priority order by default |
| Layout | How the visible starters are arranged, such as a row of chips or a stacked list |

The number of visible starters is the Rulebook's Total setting. The fallback set is the Default Playbook's starters.
