title: "Proactive message"

A proactive message is one Crossword sends without waiting for the shopper to type. It appears as a nudge from the widget while the shopper is on a page: a sizing offer after fifteen seconds of silence, or "Still deciding between these?" after they open two product pages. Each proactive message belongs to a [Journey](/orchestration/journeys), carries a "shows when" rule, and routes to a named Agent. When the shopper replies or taps a chip, the message goes straight to that Agent.

## What it contains

| Property | What it holds |
| -------- | ------------- |
| Content | The text and media the message carries |
| Embedded components | Any card or interactive component from the [Component library](/components/overview), plus an optional suggestion set |
| Presentation | How the message appears on the surface, such as a widget bubble or an expanded panel |
| Shows when | The rule that decides when it appears inside the active Journey, with optional delivery restrictions |
| Routes to | The Agent that answers when the shopper replies or taps a chip |
| Dismiss behavior | What happens when the shopper closes the message, and whether it can return |

The text and media belong to the proactive message. The cards it embeds are plain components with no rule of their own. They show because the message that carries them was delivered.

A proactive message answers one of two questions, and the answer decides where it lives. **Contextual** asks what should happen right now, given this session. On a product page, fifteen seconds idle, show sizing help. That belongs in a Journey, as a message with a "shows when" rule. **Lifecycle** asks what should happen to this person over the next hours or days. Cart abandoned, wait 30 minutes, send a message, wait 6 hours, check for purchase. That belongs in a Campaign. A Campaign step can deliver a proactive message directly. The message then carries a Campaign reference instead of a rule, and the Campaign's own delivery limits and suppression govern it. Read [Journeys vs campaigns](/orchestration/journeys-vs-campaigns#proactive-messages-which-one) for the full test.

## Rule

Because it interrupts, a proactive message carries a "shows when" rule. The message can show only while its Journey is the active one, selected by the shopper's [entry point](/orchestration/rules#entry-points). Inside that Journey, it shows when its rule is met.

| Rule field | What you can set |
| ---------- | ---------------- |
| Conditions | Page or URL, arrival source and UTM parameters, segment membership, logged in, past orders, cart contents, time on page, scroll, and inactivity |
| Condition combinations | All, any, and exclusions |
| Delivery restrictions | Frequency cap, suppression, and repeat behavior after the shopper dismisses or acts on it |

Conditions combine. A rule can require that the shopper is on a product page **and** has been idle for fifteen seconds **and** has nothing in the cart.

A message that has hit its frequency cap is skipped even when its rule is met. When the shopper moves to a page that selects a different Journey, that Journey's proactive messages apply instead.

## Examples

Two proactive messages. Each describes the configuration, not the exact copy.

### Inactivity

Reaches a shopper who has stopped on a long page without acting.

```yaml
Journey: Product Discovery
Shows when: The shopper is on a collection with many products and has not scrolled or tapped for a few seconds
Message: Acknowledges the long list and offers to pick a few
Buttons: One to ask anything, one to accept the picks
Routes to: Product Discovery Agent
Delivery: Once per session
```

### Home welcome

Introduces the assistant shortly after a shopper lands on the home page, before they open the chat.

```yaml
Journey: Default
Shows when: The shopper has been on the home page for a few seconds and has not opened the chat
Message: Introduces the assistant and what it can help with, such as discovering products and comparing options
Buttons: None; the shopper replies in the chat bar or closes the card
Routes to: Product Discovery Agent
Delivery: Once per session
```
