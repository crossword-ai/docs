The Component library is every component in a Crossword experience, in one list. A component is anything a shopper can see or interact with, from a welcome message to a section on a product page. The list splits into five families, and some components carry a rule that decides when and where they show.

| Family | What it covers | Carries a rule? |
| ------ | -------------- | --------------- |
| Conversation | What the shopper sees in the chat: messages, starters, suggestions, and the assistant reply. | Starters carry a page rule: the page they show on, and priority. Proactive messages carry a full rule. Follow-up suggestions do not, because the Agent writes them for each reply from its instructions. The welcome message does not, because it is global and set once in the Default Journey. The assistant reply does not, because the Agent composes it. |
| Cards | Structured units for products, comparisons, carts, and orders. | No. Shown inside a message, a reply, or a page section. |
| Interactive | Pieces the shopper works through step by step. | No. Shown the same way as cards. |
| Page | Sections Crossword inserts into or replaces on a merchant page. Read [Page sections](/components/page/page-sections). | Yes. A target page, a placement, and a rule. |
| Primitives | The button, input, selector, media, and text every other component is built from. | No. |

## Rules

The rule lives on the rule-based component. A starter carries a page rule: the page it shows on, and priority. A proactive message or a page section carries its own conditions and priority. A follow-up suggestion carries no rule: the Agent writes it for each reply, from its instructions. Proactive messages and page sections add timing and delivery limits. A [Rulebook](/orchestration/rulebooks) resolves the rule-based components of one type across every enabled Journey, with fallback from the Default Journey. The welcome message carries no rule and has no Rulebook. It is set once in the Default Journey and every shopper sees it.

Plain components have properties and no rule. A product card shows because something placed it: a message that embeds it, a page section that holds it, or the Agent composing the assistant reply. Read [Rules](/orchestration/rules) for what a rule can contain.

## Example

In the dashboard, the library is one screen. The five families run across the top as tabs, **Conversation** through **Primitives**, and the selected family opens a grid of component tiles, each with its name, a one-line description, and a **Rule** badge where the component carries one. Selecting a tile, such as **Welcome message**, opens its properties in a panel on the right.
