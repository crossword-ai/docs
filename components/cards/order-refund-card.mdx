title: "Order and refund status card"
description: "Order reference, status, and the actions a shopper can take"
---

The order and refund status card shows a shopper where an order stands and what they can do about it. It covers the whole post-purchase path: tracking an order, starting a return, and following a refund. The shopper gets the answer and the next action in one card instead of a link to an account page.

## Example

A signed-in shopper asks "Where is my order?" and the Agent replies with the status card for their most recent order. The header shows the order number and the date it was placed, followed by the two pairs in the order with thumbnails. A status line reads "Shipped" with the expected delivery date and a tracking link beneath it. The controls match that state: a filled **Track order** button and a text **Need help with this order?** link, while **Return these items** is absent because the order has not arrived. Once the order is delivered, the same card reads "Delivered" and offers the return button instead.

## Anatomy

| Property | What it holds |
| -------- | ------------- |
| Order reference | The order number and the date it was placed. |
| Items | The products in the order. For a return, only the eligible items. |
| Status and details | The current state of the order, return, or refund, with details such as a tracking link or a refund amount. |
| Relevant controls | The actions available in the current state, such as **Track order**, **Return these items**, or **Cancel return**. Built from the [button](/components/primitives#button) primitive. |

The controls run [Workflows](/agents/workflows). A **Return these items** button starts the Workflow that generates a return label, and the card updates as the Workflow moves through its steps. Which controls show depends on the state: an order that has shipped offers tracking, an order that has arrived offers a return.

## Where it appears

An order and refund status card never shows on its own. One of these rule-based components includes it.

- In a [welcome message](/components/conversation/welcome-message), for example when a signed-in shopper with an open order opens the widget.
- In a [proactive message](/components/conversation/proactive-message), for example when a Campaign step tells a shopper their refund has been issued and shows the amount.
- In the [assistant reply](/components/conversation/assistant-reply), where the Agent chooses it. The shopper asks where their order is or how to return something, and the Agent answers with the card. For this the Agent needs the Workflows and the order data access that fill it.
- On a page, inside a [page section](/components/page/page-sections) on an account or order page, for example a [content block](/components/page/content-block) that greets the shopper with the status of their latest order.

## Rules

An order and refund status card carries no rule. It shows because a welcome message, a proactive message, or a page section with a rule included it, or because the Agent composed it into the assistant reply. The rule that decides whether and when the shopper sees it lives on that component, not on the card. Read [Rules](/orchestration/rules).
