The order and refund status card shows a shopper where an order stands and what they can do about it. It covers the whole post-purchase path: tracking an order, starting a return, and following a refund. The shopper gets the answer and the next action in one card instead of a link to an account page.

## Anatomy

| Property | What it holds |
| -------- | ------------- |
| Order reference | The order number and the date it was placed. |
| Items | The products in the order. For a return, only the eligible items. |
| Status and details | The current state of the order, return, or refund, with details such as a tracking link or a refund amount. |
| Relevant controls | The actions available in the current state, such as **Track order**, **Return these items**, or **Cancel return**. |

The controls run [Workflows](/agents/workflows). A **Return these items** button starts the Workflow that generates a return label, and the card updates as the Workflow moves through its steps. Which controls show depends on the state: an order that has shipped offers tracking, an order that has arrived offers a return.

## Where it appears

An order and refund status card never shows on its own. One of these components includes it.

- In the [welcome message](/components/conversation/welcome-message), which is global. Every shopper sees the same one, signed in or not, so for a signed-in shopper with an open order, use a proactive message instead.
- In a [proactive message](/components/conversation/proactive-message), for example when a Campaign step tells a shopper their refund has been issued and shows the amount.
- In the [assistant reply](/components/conversation/assistant-reply), where the Agent chooses it. The shopper asks where their order is or how to return something, and the Agent answers with the card. For this the Agent needs the Workflows and the order data access that fill it.
- On a page, inside a [page section](/components/page/page-sections) on an account or order page, for example a [content block](/components/page/content-block) that greets the shopper with the status of their latest order.

## Rules

An order and refund status card carries no rule. It shows because the welcome message, or a proactive message or page section with a rule, included it, or because the Agent composed it into the assistant reply. The rule that decides whether and when the shopper sees it lives on that component, not on the card. The welcome message is the exception: it carries no rule and is global, so every shopper sees what it embeds. Read [Rules](/orchestration/rules).

## Example

A signed-in shopper asks "Where is my order?" and the Agent replies with the status card for their most recent order. The header reads "Order #1008" with a green **Arrives Tue** badge, followed by the single item in the order, Speedcat OG, with its thumbnail, a quantity of 1, and $120. Below the item a vertical timeline walks through the order's states: Order placed on Mon, 9 Jun and Packed on Tue, 10 Jun are complete, Out for delivery at 8:40 AM today is the current step, and Delivered, expected today, is greyed out. The shopper sees where the parcel is without opening an account page. Once the order arrives, the same card marks Delivered as complete and offers a return instead.
